# Expanded lobby build roadmap

This roadmap prioritizes a cohesive, impressive spawn before adding lots of disconnected content.

## Phase 0 — source and coordinate audit
- [x] Preserve the recovered original 1.0 source separately.
- [x] Assemble the repaired 1.0 datapack separately.
- [x] Repair the three oversized Shenron Valley fill commands.
- [ ] Measure the exact footprint and height of every current region function.
- [ ] Record overlaps, gaps, path endpoints, and spawn safety issues.
- [ ] Establish a disposable 1.21.1 test world and capture baseline screenshots.

**Exit gate:** coordinate map agrees with the source functions, not just estimated boxes.

## Phase 1 — central spawn experience
- [ ] Rework the plaza into a finished arrival space with a recognizable centerpiece.
- [x] Add a floating one-star Dragon Ball landmark above the player arrival pad.
- [x] Color-code the four gateway caps to match the district road markers.
- [x] Add a first landscaping pass: four symmetrical cherry-tree garden planters in the plaza corners.
- [ ] Add four clear district approaches and consistent path borders.
- [ ] Add welcome, navigation, rules, and help display areas.
- [ ] Reserve portal pads and future NPC / quest locations.
- [ ] Add lighting, planters, seating, and spawn-safe circulation.

**Exit gate:** a first-time player can arrive, orient themselves, and understand where to go without staff help.

## Phase 3 — server functionality
- [ ] Add configurable welcome / information displays.
- [ ] Add clearly separated portal / travel destinations.
- [ ] Add spawn protection guidance and player-safe arrival areas.
- [ ] Integrate NPCs, quests, shops, and leaderboards only after the actual mod / plugin stack is known.
- [ ] Add staff-only maintenance / reset procedures.

**Exit gate:** the lobby is usable as a multiplayer server hub, not just a decorative map.

## Phase 4 — atmosphere and seasonal content
- [ ] Add ambient details and small exploration rewards.
- [ ] Add optional day / night lighting treatment.
- [ ] Plan event decorations that can be enabled without rebuilding the whole lobby.
- [ ] Add seasonal variants as separate functions or datapack modules.

**Exit gate:** optional extras do not interfere with navigation or core performance.

## Phase 5 — performance and release
- [ ] Test generation time and command performance in a disposable world.
- [ ] Check for command limits, missing functions, invalid JSON, and unsupported block IDs.
- [ ] Inspect the entire lobby at ground level and from aerial viewpoints.
- [ ] Test multiplayer spawn congestion and portal arrivals.
- [ ] Package a versioned ZIP and publish installation / rollback instructions.

**Release rule:** never label a phase complete based only on documentation or static validation. In-game visual and functional checks are required.
